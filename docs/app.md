# Глава 2. Многопоточное демонстрационное приложение (`app`)

Приложение `app` спроектировано как консольная оболочка (Часть 2 ТЗ) для проверки синхронного ядра логирования. Основная задача приложения — обеспечить неблокирующий ввод сообщений пользователем из `std::cin` с последующей передачей данных в фоновый поток для физической записи.

---

## 1. Компоненты приложения и зоны ответственности

Архитектура асинхронного слоя разделена на три составляющие с четкими границами ответственности:

### ThreadManager
Класс выполняет роль потокобезопасного буфера (очереди задач) и координатора состояния приложения. Его задачи:
* Инкапсуляция стандартного контейнера `std::queue<LoggerMessage>` и защита критических секций с помощью `std::mutex`.
* Управление блокировкой и пробуждением читающего потока через `std::condition_variable`.
* Фиксация кодов ошибок `std::error_code`, возникающих при записи в фоновом потоке, и управление флагом принудительной остановки приложения.

### Функция loggerWorker (Фоновый поток)
Изолированная функция, выполняющаяся в отдельном системном потоке `std::thread`. Реализует бесконечный цикл извлечения задач:
1. Вызывает блокирующий метод `threadManager.pop()`.
2. Если метод возвращает `std::nullopt`, цикл завершается, и поток штатно прекращает работу.
3. Если задача получена, вызывает синхронный метод `lg.log()`. При возникновении сбоя записи передает полученный `std::error_code` обратно в `threadManager`.

### Функция main (Основной поток)
Является оркестратором приложения. Отвечает за:
* Валидацию аргументов командной строки и парсинг уровней важности логов.
* Инициализацию объектов `ThreadManager`, `Logger` и явный запуск потока `logger`.
* Интерактивный опрос пользователя в цикле `std::getline(std::cin, ...)`.
* Контроль критических ошибок, переданных из фонового потока, и остановку приложения.
* Гарантированный вызов `logger.join()` перед завершением процесса для предотвращения аварийного падения программы.

---

## 2. Реализация паттерна Producer-Consumer и синхронизация

Взаимодействие между потоком ввода (`main`) и потоком записи (`loggerWorker`) построено по классической схеме **Producer-Consumer**:

* **Добавление (Push)**: Поток `main` считывает строку, валидирует уровень важности и вызывает `threadManager.push()`. Метод захватывает мьютекс, добавляет объект в очередь и сигнализирует через `condition_variable.notify_one()`, после чего `main` сразу уходит на следующий виток опроса консоли, не дожидаясь окончания записи на диск.
* **Извлечение (Pop)**: Функция `loggerWorker` вызывает `threadManager.pop()`. Если очередь пуста, поток засыпает на условной переменной, освобождая процессорное время. При поступлении сигнала поток просыпается, извлекает элемент и возвращает его в виде `std::optional<LoggerMessage>`.

---

## 3. Гарантированная остановка и обработка критических ошибок

В приложении реализовано два сценария завершения работы:

### Штатная остановка
Когда пользователь вводит пустую строку в качестве сообщения, поток `main` вызывает `threadManager.stop()`, выставляя внутренний флаг завершения, и прерывает свой цикл. 
Фоновый поток `loggerWorker` продолжает извлекать данные через `pop()`. Метод `pop()` спроектирован так, что он возвращает `std::nullopt` **только тогда, когда очередь полностью опустеет** после получения сигнала остановки. Это гарантирует, что все введённые пользователем логи будут физически записаны на диск до того, как поток `logger` завершит работу и будет сшит через `join()`.

### Аварийная остановка
Если в фоновом потоке происходит сбой (например, закончилось место на диске или оборвался сетевой сокет), `lg.log()` возвращает ошибку, которая сохраняется в `ThreadManager` через `setError()`. 
На следующем шаге цикла поток `main` проверяет это состояние через `threadManager.getError()`. Обнаружив критическую ошибку, `main` выводит системное сообщение `err.message()`, прерывает работу и возвращает код `1`, предотвращая бесконечную отправку данных в неработающий канал вывода.
